# Constitution: Package Identifier Tool

**Derived from**: `package-identifier/index.html`
**Derived**: 2026-05-21

This document states the non-negotiable invariants of the Package Identifier Tool.
Every rule here is directly observable in the current implementation and MUST hold
in any future version of the tool.

---

## Article I — Delivery

1. The tool is delivered as **one self-contained HTML file** with all CSS and JavaScript
   embedded inline; no companion files are required.
2. The file MUST be fully functional when opened as a `file://` URL; no web server is
   required.
3. **No external resources** — scripts, stylesheets, fonts, images, or data files — are
   loaded at any time during the tool's lifecycle.
4. No build step, bundler, package manager, or toolchain is required to use or modify
   the tool.

---

## Article II — Data & Privacy

5. All computation occurs **exclusively in the user's browser**; no data is ever
   transmitted to a server or third party.
6. The tool maintains **no persistent state** between sessions: no localStorage, no
   sessionStorage, no cookies, no IndexedDB, no service worker cache.
7. Identifier values entered or generated by the user are **never logged or retained**
   beyond the current page session.

---

## Article III — Supported Identifier Types

8. The tool supports exactly **five identifier types**: PZN, NTIN, GTIN, PPN, and PCID.
9. Each identifier type has exactly **one canonical validation function** and one
   canonical **generation function**; these two functions form an invariant pair (see
   Article IV).
10. Adding support for a new identifier type requires providing both functions before
    the type may be exposed in the UI.

---

## Article IV — Generator–Validator Duality

11. **Soundness**: every identifier produced by a *valid* generation call MUST pass its
    own validation function (`validateX(generateX(false)) === true`).
12. **Corruption guarantee**: every identifier produced by an *invalid* generation call
    MUST fail its own validation function (`validateX(generateX(true)) === false`).
13. Invalid generation is achieved **solely by shifting the computed check digit by +1
    modulo the check's divisor** (10 for GS1 MOD-10 and PZN MOD-11 outputs; 97 for
    PPN MOD-97); no other corruption strategy is used.
14. **PCID is exempt** from Articles IV(11–13): every structurally valid UUID is a
    valid PCID and no well-defined corruption path exists; the "Generate invalid" option
    MUST be disabled for PCID.

---

## Article V — Algorithm Specifications

These rules encode the exact algorithm each validation function implements.
Any change to an algorithm invalidates this article and requires a revision.

15. **PZN** — MOD-11 over 7 digits with weights `[1, 2, 3, 4, 5, 6, 7]`;
    `check = sum % 11`; identifiers where `check === 10` are structurally unallocated
    and MUST be rejected; identifiers matching the dummy set
    `{00000000, 22222222, 33333333, 44444444}` MUST be rejected regardless of check
    digit.

16. **GTIN** — GS1 MOD-10 over all digits except the last, with weights alternating
    `3, 1` from the rightmost non-check digit leftward;
    `check = (10 − (sum % 10)) % 10`; valid input lengths after stripping non-digit
    characters are `{8, 12, 13, 14}` digits; all other lengths MUST be rejected.

17. **NTIN** — a GTIN-13 with the mandatory GS1 Germany prefix `4150`; the GTIN MOD-10
    rule (Article V §16) applies in full; the 8 digits at positions 4–11 (0-indexed)
    of the 13-digit body encode a PZN that MUST be extracted and validated
    independently (see Article VI).

18. **PPN** — an optional `9N` prefix followed by exactly 12 digits; the 2-digit check
    pair equals `(Σ charCode(d_i) × (i + 2)) % 97` over the first 10 digits
    (multiplier starts at 2 for the first digit, increments by 1 per digit), zero-
    padded to 2 digits; the 8 digits at positions 2–9 of the 12-digit body encode a
    PZN that MUST be extracted and validated independently (see Article VI).

19. **PCID** — any UUID matching RFC 4122 versions 1–5; the regex pattern is
    `^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`
    (case-insensitive).

---

## Article VI — Embedded PZN

20. NTIN and PPN structurally contain a PZN. Whenever either type is involved in a
    validate or generate operation, the embedded PZN MUST be **extracted and validated
    separately**, and its result MUST be shown alongside the outer result.
21. If the outer identifier is too short or malformed to yield an 8-digit PZN candidate,
    the embedded PZN result MUST indicate that extraction failed (warn state).
22. The validity of the embedded PZN is **independent** of the validity of the outer
    identifier: an outer-valid NTIN may contain an inner-invalid PZN, and vice versa.

---

## Article VII — User Interface

23. The interface provides exactly **two top-level modes**: Generate and Validate,
    accessible via a tab control. No additional top-level modes may be added without
    amending this constitution.
24. **Every operation** (generate or validate) MUST produce an explicit visual outcome:
    success (green) or failure (red). A silent, empty, or ambiguous result is
    prohibited.
25. An **empty identifier input** in Validate mode MUST produce an error result before
    any algorithm is invoked; the algorithm dispatch path MUST NOT be reached with an
    empty string.
26. The **"Embed valid PZN"** option MUST be shown if and only if the selected
    identifier type structurally encodes a PZN (currently NTIN and PPN); it MUST be
    hidden for all other types.
27. The **"Generate invalid"** option MUST be disabled and its checkbox cleared whenever
    the selected type is PCID (Article IV §14); it MUST be re-enabled when any other
    type is selected.

---

## Article VIII — Clipboard

28. Copy-to-clipboard uses `navigator.clipboard.writeText()` as the primary mechanism.
29. A failed clipboard write MUST be silently ignored; no error or warning is surfaced
    to the user.
30. On a successful copy invocation, the button label MUST change to `Copied!` and
    revert to `Copy` after **1.5 seconds**.
